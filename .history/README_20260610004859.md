# Edits Viewer

A local-first video browser for people who work with a lot of video files. Point it at a directory, and it gives you a searchable, taggable table or grid of everything in there with inline previews, a floating player, and in-place renaming/tagging/deletion.

Built with Express and better-sqlite3, served over the local network, styled like a Windows XP-era utility app.

---

## Features

**Filesystem sync** — Scans a local directory for video files (.mp4, .mov, .avi, .mkv, .webm, .wmv, .flv, .m4v, .mpg, .mpeg) and keeps its database in sync. Detects new files, updated files, and files that have been removed from disk. Re-scan on page load or manually with the Rescan button.

**Dual view modes** — Toggle between a traditional table (list view) with columns for preview, filename, tags, favorite, and actions, or a grid of cards showing thumbnails. Your choice persists in localStorage.

**Hover preview** — Hover over any thumbnail cell to get a floating, muted video preview after a 100ms delay. Helps you identify clips at a glance without opening anything. Positioned intelligently to stay on-screen.

**Floating video player** — Click a thumbnail to open a resizable, draggable player window. Supports seek, play/pause, volume control, mute, and fullscreen. Keyboard shortcuts for all controls. Draggable by the title bar.

| Key | Action |
|---|---|
| Space | Play / Pause |
| ← / → | Seek back/forward 5s (hold Ctrl for 30s) |
| ↑ / ↓ | Volume +10 / -10 |
| F | Toggle fullscreen |
| M | Toggle mute |
| Esc | Close player / exit fullscreen |

**In-place filename editing** — Click a filename in list view to edit it inline. Extension is preserved automatically. Renames the file on disk and updates the database. Enter to save, Esc to cancel.

**Tagging** — Click the tags cell in list view, type a tag, and press Enter to add it. Tags are lowercased and deduplicated. Click the × on any tag badge to remove it. Tags are searchable from the search bar.

**Favorites** — Click the star button to toggle a video as favorite. Filter the view to show only favorites with the checkbox in the toolbar. Globally: with a video row hovered, press `F` to toggle.

**Quick actions** — Each row has an "Open in VLC" button (opens the file with the default system player) and a "Delete" button (permanently deletes the file from disk with a confirmation dialog). Press Delete on a hovered row as a shortcut.

**Search** — Filters both filename and tags in real-time as you type. Press `/` to focus the search bar from anywhere.

**Thumbnails** — If FFmpeg is on your PATH, thumbnails are auto-generated on demand (one frame at 1s, scaled to 320px wide). Generated thumbnails are cached in a `thumbnails/` directory and reused.

**Keyboard shortcuts (global, when no input is focused)**

| Key | Action |
|---|---|
| / | Focus search bar |
| Delete | Delete the hovered video (with confirmation) |
| F | Toggle favorite on the hovered video |

## Tech Stack

| Layer | Technology |
|---|---|
| Backend | Node.js + Express |
| Database | SQLite via better-sqlite3 (WAL mode) |
| Frontend | Vanilla JS, no framework |
| Styling | CSS (2000s web aesthetic) |
| Thumbnails | FFmpeg (optional, auto-detected) |

The database is the source of truth for app state (tags, favorites, status). The filesystem is the source of truth for media. The scanner reconciles the two on startup and on demand.

## Getting Started

### Prerequisites

- **Node.js** >= 18
- **FFmpeg** (optional — for thumbnail generation; auto-detected at startup)

### Install

```bash
git clone <repo-url>
cd edits-viewer
npm install
```

### Configure

Edit the `EDITS_DIR` constant in both `db.js` and `server.js` to point at your video directory:

```js
const EDITS_DIR = 'C:\\Users\\You\\Videos\\Edits';
```

Or, if you're on Linux/macOS:

```js
const EDITS_DIR = '/home/you/Videos/Edits';
```

The server listens on port **4000** by default — change `PORT` in `server.js` if needed.

### Run

```bash
npm start
```

Or double-click `start.bat` (Windows) — it opens the browser automatically.

The server will:
1. Initialize the SQLite database (`edits.db`)
2. Scan the configured directory for video files
3. Start serving at `http://localhost:4000`

## API Reference

All endpoints are ID-based for stable identity across renames.

| Method | Route | Description |
|---|---|---|
| GET | `/videos` | List all active videos (triggers a background scan first) |
| GET | `/video/:id` | Stream a video file (supports range requests for seeking) |
| GET | `/thumbnail/:id` | Serve or generate a thumbnail for a video |
| POST | `/rename/:id` | Rename a file on disk + update database |
| POST | `/delete/:id` | Permanently delete a file from disk + soft-delete in DB |
| POST | `/favorite/:id` | Toggle favorite status |
| POST | `/tags/:id` | Add/remove a tag (`{ action: "add"|"remove", tag: "string" }`) |
| POST | `/open/:id` | Open video in the default system player |
| POST | `/scan` | Manually trigger a directory rescan |

### Response format

List endpoints return `{ videos: [...] }` where each video object is:

```json
{
  "id": 1,
  "filename": "my_clip.mp4",
  "tags": ["tag1", "tag2"],
  "favorite": true,
  "hasThumbnail": true
}
```

Mutation endpoints return `{ success: true, id, ... }` or `{ error: "message" }`.

## Design Notes

The UI is intentionally styled after Windows XP-era utilities — gradient title bars, beveled buttons with inset/outset borders, monospace fonts, a Classic theme scrollbar, and a fixed footer. It's nostalgic but lightweight: zero frontend dependencies, everything is vanilla JS and CSS.

The floating player can be resized from the bottom-right corner and remembers its position during a session through drag state. The confirmation dialog for deletions is rendered as a DOM overlay rather than the native `confirm()` to avoid blocking the event loop and to match the visual style.
